# Live correction (camera)
- Keep per-exercise rules pure in `src/lib/liveCorrection/exercises/` (one file per rule, registered in `index.ts` most-specific first, thresholds as exported constants; `squat` wraps the unchanged `squatAnalysis.ts`) and pick the rule by name with `matchExerciseRule`, saving its id in `camera_sessions.exercise_rule` and load MediaPipe only inside the lazily imported `LiveCorrectionScreen`, so the pose library never enters the initial bundle and the rules stay testable without a camera.
- Access is gated by `students_profile.premium_camera` and the per-student `camera_depth_level` (both admin-only, guarded by RLS plus the `guard_premium_camera` trigger) and `has_premium_camera()` for `camera_sessions` inserts; admins always pass so they can test via `/correcao-ao-vivo-teste`.
- Depth levels are stored as their own names and the database converts legacy names on write (`normalize_camera_depth_level`), so screens opened before a rename keep saving valid values.
- Rules differing from the full-body side-view flow declare it through optional `ExerciseRule` fields (`isBodyVisible`, `stillPoints`/`stillScale`, `skeleton`, `lostMessage`, `startHint`, `speakOncePerSeries`, `excludeKeywords`, `notReadyMessage`), the optional `exerciseName` argument of `createCounter` (in-rule variants such as Scott curl) and optional counter hooks (`resting`, `flush`), so earlier rules leave them unset and keep their exact behavior; arm/shoulder rules share `exercises/arms.ts` (arm side, upper-body visibility, lockout hold).
- Timed rules (`timed: true`, e.g. plank) return a `TimedCounter` whose pure `track()` drives the stopwatch and `summary()`; the screen saves them through `timedToSessionSummary` (total_reps = seconds in position, complete_reps = seconds in good position) so camera_sessions and "Salvar na série" keep a single shape.
- The coach's recorded voice is keyed by phrase: `src/lib/liveCorrection/voice/phrases.ts` derives the catalog from the rule messages (so new messages appear automatically), the screen keeps speaking code texts and `VoiceQueue` maps each sentence to an approved clip or falls back to speechSynthesis one segment at a time; `browserVoice` treats a downloaded clip as available regardless of AudioContext state and on iPhone/iPad plays it first through pre-created, gesture-primed <audio> elements with Blob URLs (Web Audio is muted by the silent switch there, so it is only the lazily decoded fallback), elsewhere Web Audio first with <audio> as fallback, TTS only if both fail, `unlock()` runs synchronously on every tap of the camera screen, and diagnostics stay in the pure `voice/status.ts`, because iOS suspends/interrupts the context after camera, calls or background; generation is admin-only in `supabase/functions/coach-voice` and clips live in the private `coach-voice` bucket, read through `coach_voice_approved()`, so editing a recording's text never changes what the camera looks up.
