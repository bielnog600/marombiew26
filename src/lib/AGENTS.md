- Plan translation (`planTranslation`, `planTranslationDisplay`, `supabase/functions/translate-plan`) is display-only and never blocks loading: the server extracts only displayed strings, caches pairs in plan_translations by content hash (publish trigger prewarms for students whose app_language is 'en'), and the app swaps text through those pairs while all logic reads the Portuguese original, so a slow AI cannot freeze screens or alter data.
- The student photo scanner reuses FoodScanner: pure `src/lib/foodPhotoScan.ts` owns lookup order, unit portions and meal-log rows; scanned items go into `meal_weigh_logs` with `origem='escaneado'` so day totals/rebalance reuse the weigh path.
- TABATA rules live in pure `tabataRules.ts`: the Ajuste Rápido day selector resolves the latest plan per weekday (load it / same plan / move-on-save) so a save never lands on another day's plan; the generator sends each day a quick-setup catalog (no bar/plate/smith/machine, no arm-support moves on upper-body days), then swaps slow-setup names deterministically and only warns about block variety, week repeats and the day's workout, so saved plans and the player format stay unchanged.
