# Pesar refeição
- "Pesar refeição" keeps rules pure in `src/lib/mealWeigh` (macros via nutritionEngine, base matching, tare check, planned×weighed) and reads photos through food-scanner's `weigh` action (same official Claude call, `has_premium_scale` checked before the AI); logs are insert-only in meal_weigh_logs and the published diet stays untouched.
- Diet-food mode (`read_weight`, reading only the display) scales the plan item's own macros to the weighed grams and stores `indice_plano`, which comparison pairs before name similarity, so weighing the planned amount always equals the planned macros.
- Scan-mode requests and repeat detection live in `buildScanWeighRequest`/`resolveScanWeigh` (pure), and the screen reads items through refs, so every item after the first always carries the previous photo and a repeated AI answer is never auto-accepted.
- The weighing screen renders through a portal and hides BottomNav via `useHideBottomNav`, because page containers (overflow/transform) otherwise trap a fixed overlay beneath the nav.
- The day's record of a weighed meal is the newest meal_weigh_logs row per (log_date, meal_index): MinhasDietas overlays it via `overlayDayWeighLogs` (foods rebuilt from the log's planned snapshot, unweighed choices and extras), locks it from rebalancing and marks daily_tracking through the existing toggle, so totals and future meals follow what was eaten without a second consumption store; older rows stay as admin history.
- Editing or deleting a confirmed item (top chips, item list, summary, and "Editar pesagem" of a saved meal) goes through the pure `editItems.ts` (`weighFoodForItem`, `editWeighedItem`, `removeWeighedItem`, `startFromWeighLog`) and only replaces the item list; totals, planned×weighed and the tare accumulator stay derived from that list (tare is recomputed live, never stored in the draft), a deleted plan food becomes "Não comi", a student-swapped food sets `alimento_corrigido` so the AI's name stops counting for matching, and saving an edit inserts a new meal_weigh_logs row so the newest-row-wins rule replaces the day record without updates.
- Auto capture keeps its rules pure in `autoCapture.ts` (32×24 grayscale frame diff, motion → ~1.5 s still → 3-2-1 → fire, cancel on motion, food/plate box inside the guide) while `useAutoCapture` only samples the video and lazily loads MediaPipe's ObjectDetector (efficientdet_lite0, 10 s timeout, stability-only fallback); it fires once and is re-armed only by "Próximo alimento"/"Tirar de novo"-style returns to the camera, so one scene never triggers repeated AI calls.
